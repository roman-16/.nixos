# BTW

The aside follows this block. It never changes what is being done right now.

## Sort it

- A question: answer it.
- A change, a feature, a fix, anything asked to be done: note it for after.
- Nothing came with it: ignore it and keep working.

## Answering a question

- A few sentences, in chat. No file, no report.
- From what is already in context. One or two lookups if the answer would otherwise be a guess; if it needs real research, say so rather than doing it.
- Answer what was asked, not the task it hints at. It is not a correction of the work in flight and not something to fold into it.

## Noting a request

- One line back: what you took down, and that it follows the current work. No plan, no estimate, no questions about it yet.
- Do not start it, do not fold it into the work in flight, do not let it bend the current approach.
- Carry it until the work in flight is done, then do it as its own piece of work, without waiting to be asked again.
- If it needs a decision from the user, ask when you get to it, not now.

## Then keep working

- Continue in the same message, straight into the next step of what was interrupted. No "shall I continue", no recap of what is already done, no re-planning.
- If nothing was in flight, handle the aside now: the answer, or the requested work, is the whole reply.
- If the aside proves the work in flight is wrong or pointless, say so in one line and stop there for the user, rather than continuing into it.
